# Useful Tools and Resources

Tools, papers, and resources I've come across and want to try or keep track of.

## Tools

- **AutoArXiv (alphaXiv)** — Swap `arxiv` for `autoarxiv` in any arXiv paper URL to hand the paper to an AI agent that clones the linked GitHub repo, resolves setup issues (dependencies, paths, environment, hardware), and designs a minimal reproduction (smaller model, fewer steps, single GPU) to test whether the paper's headline claim holds, with the run logged live. Useful for quickly checking whether a paper's code actually reproduces its result before investing a full weekend in it.
- **[Academic Research Skills](https://github.com/Imbad0202/academic-research-skills)** — A Claude Code skill suite covering the full academic pipeline (research → write → review → revise → finalize) via four skills: Deep Research, Academic Paper, Academic Paper Reviewer, and Academic Pipeline, with human-in-the-loop integrity checks for citations and claims. Could help structure literature reviews and paper drafts while keeping a human in the loop on correctness.
- **[freephdlabor](https://www.linkedin.com/feed/update/urn:li:activity:7499284739669958656/)** — An open-source multi-agent framework that coordinates specialized agents to take a research idea through experiments to a manuscript draft, with task-based launching, domain customization, and HPC integration. Worth trying for automating parts of the experiment-to-draft pipeline on compute I already have access to.
- **[SciEval](https://www.linkedin.com/feed/update/urn:li:activity:7500032301796507650/)** — A "living knowledge base" for scientific/engineering AI agent evaluation that combines human-designed knowledge structures with AI agents that continuously maintain and synthesize papers by methodology, domain, and scientific activity. Could help keep a running, organized map of papers instead of an ever-growing flat reading list.
- **[OpenKB](https://www.linkedin.com/feed/update/urn:li:activity:7492671509266677760/)** — A knowledge-base system (inspired by Andrej Karpathy) where an LLM compiles what it reads into a growing wiki of interconnected concept/entity pages using tree-indexing instead of a vector database. Interesting alternative to RAG for accumulating durable, structured notes across many papers rather than re-deriving context each time.

## Papers and Reading

- **[Mathematics in the Age of AI](https://www.linkedin.com/feed/update/urn:li:activity:7500811816562921474/)** (Terence Tao) — An essay arguing that instead of debating whether AI can do research-level math, the math community should explicitly define its goals and values, favoring proof verification, exposition, and canonicalization over raw problem-solving speed. Good grounding for thinking about how AI tools should (and shouldn't) be used in my own math-heavy paper work.
- **[Machine Learning for Physicists](https://www.linkedin.com/feed/update/urn:li:activity:7490174881985363968/)** (Caio Laganá Fernandes, book in progress) — Teaches machine learning fundamentals through physics concepts, starting with a single neuron as linear regression. A different angle on the math foundations I'm already building from scratch with NumPy/PyTorch.
- **[A Mathematical Introduction to Diffusion Models](https://arxiv.org/html/2608.16753v1)** (Jianfeng Lu) — A self-contained, proof-oriented mathematical treatment of diffusion models connecting classical sampling methods to modern score-based approaches. Directly relevant to the DDPM/latent-diffusion/DiT/flow-matching papers already queued in the main [ReadMe](ReadMe.md).
